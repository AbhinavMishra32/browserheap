What sleeping costs

      

        
Refs reset on wake
Snapshot refs like e12 belong to the page as it was. Take a new snapshot after a wake.

        
Page-only state goes
An open menu or a half-played video. URL, scroll, cookies and logins come back.

        
Live tabs cost Chrome
A live tab is a real Chromium page. Keep more awake with --live.

        
MCP is next
Today it's a skill, a CLI and an SDK. An MCP server is on the way.

      

    

  


  

    

      

        
        
      

    

  


  

    

      
A browser that lets agents keep every tab

      
The fixes on offer close tabs or restart Chrome, and both lose the agent's work. Browserheap puts idle tabs to sleep instead.

    

  


  

    

      

        
Sleeping tabs

        
Two tabs awake, the rest asleep

        
The two tabs your agent used last are live Chromium pages. Every other tab sleeps: it keeps its URL, scroll, text and cookies, and gives back its memory. Touch it and it wakes where it was, in about a quarter of a second.

Handles that survive sleep

        
Your agent's code never notices

        
Other agent browsers hand out raw pages that go stale when a tab closes. Browserheap's pages and locators belong to the tab, so a page kept in a variable keeps working while its tab sleeps and wakes underneath.

Works with your agent

        
A skill, a CLI, or an SDK

        
Drop the skill into Claude Code or Codex and your agent learns the loop: open a page, read its snapshot, act with Playwright-style code, check what changed. Or drive it from a shell, or build it into your own agent with startSession().
