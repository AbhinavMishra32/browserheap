Agents leave tabs open. We measured what that costs.

The same 30 websites in Browserheap and seven other agent browsers, on one 8 GB machine. Everything we measured, including where we lost.

Summary

    01Why tabs pile up

    An agent doing research works like a person with too many tabs, minus the habit of closing them. It searches, opens five results, follows two links into docs, checks a forum thread and writes its answer. Every page it opened is still there, rendering, running scripts and holding memory, and the agent will rarely look at most of them again.

    People running agents feel this. On agent-browser, users report 60 or more tabs piling up with the browser above 100% CPU; the fix being discussed is an idle timeout that closes the whole browser. On browser-use, long-running agents collect tabs for days, and the suggested fixes are to close old tabs or restart Chrome.

    Both fixes throw work away. A closed tab is a source the agent can no longer go back to. A restarted Chrome has lost the agent's logins. We wanted to know whether a browser could keep every tab the agent opened and still use little memory, and whether the agent would notice.

    02What we built and what we compared

    Browserheap keeps the 2 tabs the agent used most recently as live Chromium pages. Every other tab sleeps: its page is closed and the tab keeps what it needs to come back as it was: its scroll and every scrolled panel's, filled-in fields, focus, sessionStorage, back/forward history and the agent's snapshot refs, plus its title and text. The agent can still read a sleeping tab. When it clicks, types or reads from the live page, the tab wakes as it was, with the same cookies. Tabs holding text the agent typed but hasn't sent never sleep.

    The agent never sees any of this. Its code holds pages and locators that belong to the tab, not to a Chromium page, so a page kept in a variable still works after its tab slept and woke.

    We compared it with the agent tools people use today, each with its default settings: agent-browser, Stagehand, browser-use and Playwright MCP, plus plain headless Chrome. All five run Chrome underneath. We also included two browser engines built to be light: Lightpanda, which doesn't lay out or draw pages, and Obscura. We measured Browserheap 0.3.0 twice over: on Chromium, its default, and with --headless-shell, on Chromium's headless shell, the lighter build headless tools use; the switch at the top picks which one every number shows. To see how much of the difference is Browserheap blocking ads and trackers, we also ran the same headless Chrome with Browserheap's blocking turned on.

    03Memory, 1 to 30 tabs

    Each browser opened the same 30 real websites one after another, from Wikipedia and MDN to The Verge, Bloomberg and Amazon, and never closed any. After each page loaded we summed the memory of every browser process.

    274ms

    The cost of sleeping: the median time to wake a tab, over every one of the 30, from the agent's click to the page being ready to use.

    Past 30 tabs

    Thirty tabs is a long research task. Agents that run for hours open more. We kept going to 100 tabs, opening the same 30 sites again from the top, and stopped each browser once it used 6.5 GB of the sandbox's 8 GB, or when it crashed.

    While the agent does something else

    Open tabs don't sit still. News sites refresh, ads rotate, videos autoplay and analytics scripts keep reporting. After the 30 tabs were open we left each browser alone for 10 minutes and sampled its memory and CPU every 15 seconds. This is what idle tabs cost while the agent is thinking, or waiting on a model.

    How many tabs to keep live

    Two live tabs is the default because an agent usually works in one page and glances at another. An agent that switches between more pages can keep more awake. This is what that costs at 30 tabs.

    04Many agents, one machine

    Memory per tab decides how many agents fit on a machine. We started 10 agents on one sandbox, each with its own browser, and had them open tabs at the same time, one round at a time, up to 10 tabs each. Each agent read different sites.

    05Can an agent still work in it?

    Low memory is easy if you give up on parts of the web. We wrote 19 tests for the things agents actually do, from clicking a button to clicking inside an iframe from another site, reading a web component and taking a screenshot. Each ran through Playwright on a small test site, in a fresh browser, with no AI model involved.

    Browserheap passed all 19, like Chrome, because it is Chrome. Lightpanda failed 7: iframes, web components, element positions, clicking at a position, scrolling to load more, popups and screenshots. Several of those follow from not drawing pages. Its screenshot returns text, so we check the colour of a pixel rather than trusting that a file came back.

    What waking costs

    Every time the agent goes back to a sleeping tab, it waits for that tab to wake. With all 30 tabs open, we woke each one in turn and timed it, and compared that with how long the same page took to load the first time.

    06Do real sites work?

    We loaded 60 real sites across 6 kinds (docs, news, shopping, code and forums, web apps and plain information pages) one at a time. A page counts as the same content as Chrome's when it shows at least 60% of the distinct words Chrome's page shows, counted only where Chrome loaded the page.

    Lightpanda got past bot walls that stop headless Chrome on CNN, Best Buy, Zara, Airbnb and Spotify, which is a real advantage. Obscura timed out or showed nothing on The Verge, Al Jazeera, Amazon, Target, Booking and Twitch.

    08Limits and fairness

    • Three runs where it matters, one elsewhere. Memory at 30 tabs and waking ran 3 times each; every chart shows the median run, and the raw data has all three. Idle, 100 tabs, many agents, actions and real sites ran once.
    • The sandboxes run as root, where Chrome only starts without its own sandbox. agent-browser, Stagehand and Playwright turn it off themselves; Playwright MCP and browser-use got their own flag for it.
    • Lightpanda holds one page per connection, so each of its tabs had its own connection, and its tabs didn't share cookies. Obscura needed its flag to reach the local test site.
    • The tools' own processes are left out. We count only browser processes, not the Node or Python process driving them. That favours the others.
    • Ads and trackers are blocked in Browserheap and not in the others, which run with defaults. Blocking makes each live page lighter too, so part of the gap per live page comes from it. The growth with tab count does not: Browserheap never has more than 2 live pages.
    • The later runs hit sites from up to 20 sandboxes at once. Some sites blocked more often in those runs, so their "pages that loaded" counts are a little lower than in the first memory run. A blocked page still counts as an open tab.
    • Waking was timed on the Browserheap side only. The first-load times next to it come from the same run, so both include the same network.
