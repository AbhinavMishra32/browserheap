agent-tabs · memory benchmark · 15 Oct 2026

30 tabs in 556 MB. The others need 3.5–4.5 GB.

Six agent browser tools opened the same 30 real websites as tabs, one after another, on the same clean E2B machine. We measured the browser's memory after every tab. agent-tabs barely grows; every other tool grows by about one Chrome tab's worth each time.

      How it was measured

      The machine

      One E2B sandbox for all six tools, run one after another: . Each tool started fresh and was closed before the next.

      The measure

      The sum of PSS (proportional set size) from /proc/<pid>/smaps_rollup over every browser process the tool started. PSS counts memory shared between processes once, split between them. The tool's own Node or Python process is left out, which favours the others.

      The tools, with their default settings

        What a tab is

        Each tool opens a site the way an agent would through its own interface (a new tab per site), waits for the page, and reads its text. A page "worked" when it showed more than 200 characters. Then the next site opens; no tab is ever closed.

        What agent-tabs does

        2 tabs live at a time; the others sleep as a saved URL, title, scroll position and text, and wake when the agent uses them again ( to wake the first tab at the end of this run). It also blocks ads and trackers. Tabs with unsent typing never sleep.

        Fairness notes

        The sandbox runs as root, where Chrome only starts without its sandbox; agent-browser, Stagehand and Playwright turn it off themselves, and Playwright MCP and browser-use were given their own switch for it. One run per tool. Raw results: bench/launch/e2b-30-tabs/.
